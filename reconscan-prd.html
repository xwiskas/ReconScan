01

Summary

ReconScan is a web application that acts as a friendly control panel for the scanning phase of a penetration test. It wraps the real, industry-standard tools — nmap, masscan, nuclei, nmap NSE scripts, and web scanners like nikto, whatweb and gobuster — behind a clean dashboard that explains what each tool and option does, shows the exact command before it runs, streams live results, and interprets those results in plain English with a suggested next step.

It's built for someone new to cybersecurity — every screen teaches — while still exposing the full advanced power of the underlying tools. The engine runs on Kali Linux (where the tools live) and is used from a browser on any device, with no login (LAN-only). A built-in Demo / Learn mode lets you explore every feature with realistic sample output before firing a single real scan.

02

Context & problem

Recon is done. ReconScan owns the next step in the pentest lifecycle and bridges into enumeration via service/version detection:

Recon ✓→ Scanning→ Enumeration→ Exploitation→ Reporting

Recon output (a list of hosts / IPs / URLs) imports straight in as targets — no retyping.

Beginners hit two walls at this stage. The tools are cryptic — nmap -sS -sV -O -p- --min-rate 1000 -T4 means nothing to a newcomer, and a wrong flag can be slow, noisy, or useless. And the results are cryptic — a wall of ports and banners doesn't tell you what matters or what to do next. ReconScan removes both walls without hiding the real tools, so you learn the actual craft with training wheels you can take off as you grow.

03

Goals & non-goals

Goals

  • Teach while doing — every tool, option and result explained in plain language.
  • Never click blind — always show the exact command and why, before it runs.
  • Genuinely powerful — full access to the real tools, no artificial limits.
  • Safe by default — sensible defaults, guardrails, authorization acknowledged.
  • Testable safely — Demo mode plus support for legal practice targets.
  • Produce a deliverable — export findings to a class-ready report, your choice of format.

Non-goals

  • Not an exploitation tool — no exploits, payloads, or Metasploit. Scanning & enumeration only.
  • Not a recon tool — recon is done; we only import its output.
  • Not a CLI replacement — it teaches the command line, it doesn't hide it forever.
  • Not for unauthorized targets — the app gates scanning of anything you don't have permission for.
04

Design principles

01 · Clarity

Explain everything

No unlabeled buttons. Hover for a tooltip, click "?" for a deeper explanation — the same pattern everywhere.

02 · Transparency

Show the command

The generated CLI command is always visible and copy-able. This is the core teaching feature.

03 · Freedom

Guardrails, not walls

Warn and confirm on risky, slow, or noisy actions — but never forbid learning.

04 · Progression

Progressive disclosure

Beginners get a clean guided flow; "Advanced" reveals raw flags and expert options one click away.

05 · Meaning

Interpret, don't dump

Results always carry a plain-English "what this means / what's interesting / what to do next."

06 · Safety

Safe by default

Conservative timing and scope defaults, Demo mode available, authorization acknowledged up front.

05

UI / UX direction

A clean, light dashboard — calm and modern, not a cluttered "hacker console." A simple left-nav layout keeps everything one click away:

DashboardTargetsNew ScanResultsReportsLearn / Glossary

The guided path is front and center; advanced options live behind an "Advanced" toggle. Every tool, option and result uses the same "?" affordance and the same what / why / next structure — learn the pattern once, know it everywhere. It's always obvious whether you're in Demo mode or running real scans, and whether a scan is queued, running, or done.

06

Signature feature — the command preview

Before any scan runs, ReconScan shows the exact command a pro would type, with every flag explained. Hover a flag to learn what it does. This is what turns "clicking buttons" into "learning the craft."

Command preview · Goal: identify services on target
$ nmap -sV -O -p 1-1000 -T4 10.10.14.7
-sV detect service & version -O guess the operating system -p 1-1000 scan the first 1000 ports -T4 faster timing (a bit noisier) 10.10.14.7 your in-scope target

Every explanation is copy-able and links into the glossary. The "-T4" chip is exactly the kind of choice that triggers a friendly "here's the trade-off" confirmation (see §07).

07

Legal, safety & authorization

Scanning a system you don't own or have written permission to test is illegal in most places. Because ReconScan makes scanning easy, it must make responsible use easy too.

A1

Authorization acknowledgement

Each project records what authorizes it — class lab, your own VM, scanme.nmap.org, an instructor scope doc.

A2

Scope allow-list

Targets live in a defined scope. Scans of anything outside it are blocked with a clear warning.

A3

Guardrails on aggressive options

Noisy or slow choices (-T5, full -p-, aggressive NSE) get a plain-English "what & why" confirm.

A4

Audit log

Every scan — command, target, time — is recorded. Good practice, and useful for your class report.

A5

Injection-safe execution

Commands are built as validated argument arrays. User input is never spliced into a shell string.

A6

Authorized-use notice

An unmissable first-run notice links to a plain-English ethics & legal primer.

Note on "no login." Because there's no authentication, the backend must only listen on localhost or your trusted LAN — never expose it to the open internet. This is designed in so it can't be forgotten.
08

Architecture

Engine on Kali, client anywhere. The backend runs where the tools are installed and serves the UI to your browser over the LAN. Demo mode swaps real tool calls for realistic fixtures — same UI, zero risk.

Browser client
Windows / any device
  • React web UI
  • Guided scan builder
  • Live results view
  • No login (LAN only)
⇄
HTTP
+ WebSocket
Kali Linux host
Engine + real tools
  • FastAPI orchestrator & queue
  • Output parsers → structured findings
  • nmap · masscan · nuclei · nikto …
  • SQLite: projects · scans · results

Long scans stream progress and output live; you can stop a running scan at any time. The same backend can later be packaged as Docker to run anywhere without a Kali install.

Data model sketch

Project      (id, name, authorization_note, created_at)
  ├─ Target   (id, project_id, value, type[host|ip|cidr|range|url], in_scope)
  ├─ Scan     (id, project_id, tool, goal, command_args[], status, is_demo, timing)
  │     ├─ RawOutput  (scan_id, stdout, stderr, exit_code)
  │     └─ Finding    (id, scan_id, target, type[port|service|os|vuln|web],
  │                     data{port, proto, state, service, version, cve, severity},
  │                     interpretation, suggested_next_step)
  └─ AuditEntry (id, project_id, action, command, timestamp)

# Command-injection safety: target/port values are validated against strict
# patterns and passed as individual args — never assembled into a shell string.
